# 技术实现

> 主 README 讲「更快」，本文讲「怎么做到更快」以及「还能怎么更快」。

## 请求体积是怎么压下来的

问答模式的每一次请求都带着全部工具 schema 和系统提示词，所以省下的每一 KB 都会在**每一轮**重复省一次。这一版做了五件事：

| 措施 | 做了什么 | 效果 |
|---|---|---|
| 完整人格 | `persona.complete: true`，不再继承编码 Agent 的交付物指引、文件引用规则、checkout 路径与 GUI URL | 系统提示词 **6.1 K → ~1.2 K** 字符 |
| 并发检索 | 提示词要求把独立检索放进同一条回复并发发起；`searchMaxQueries: 10` 允许一次调用覆盖多个子事实 | 多个子问题不再逐轮串行，总耗时由最慢的一路决定而非各路相加 |
| 检索收紧 | 一次检索 5 条、每条摘要 400 字符 | 单次检索输出 **~8 K → ~2 K** 字符 |
| 抓取收紧 | `fetchMaxOutputChars: 60000`、`fetchTimeoutMs: 45000` | 单页上限从 ~5 万 token 降到 ~1.5 万，且适配分层抓取的超时 |
| 结果裁剪 | 挂上 `tool-result-pruner`（阈值 8 KB，保留首尾） | 超长网页正文不再原样驻留并逐轮重发 |

## 并发的边界

DSH 的工具执行器本来就用滚动池并发执行同一批工具调用（默认上限 10 路），`web_search` 内部对多个 query 也已经是并发请求再合并。插件这一层要做的是让模型**真的**把这些独立调用放进同一条回复——旧提示词鼓励「先搜一次，不够再补一次」，那才是串行感的来源。

所以这次改的是人格提示词与查询上限：**没有引入任何运行时代码，也不改引擎配置**。只有后一步依赖前一步结果（例如先搜到 URL 再抓取正文）时才需要分轮，这是边界而非缺陷。

## 为什么结果裁剪不能省

宿主层已禁用全局 `tool-result-pruner`，预设不挂就等于每个抓取结果都按原文进上下文，并在后续每一步重复发送。裁剪是模型无关、可重放的：保留超长结果的首尾，中间标记省略。

## `complete: true` 的细节

`complete: true` 不会动工具 schema，也不会动运行时上下文——工作目录、沙箱与审批策略、当前时间照常注入，只是提示词段落被这一段替换。代价是顺手丢掉了引擎清单那段自动注入的文字，所以人格里补了「不要自行更改引擎配置」这一条。

## 工具数量实测

| 场景 | 工具数 | 工具 schema | 系统提示词 |
|---|---|---|---|
| 标准模式 | 44 | 42.1 KB | — |
| 问答模式（装了 `dsh-free-search`） | 17 | 11.7 KB | 1.2 K 字符 |
| 问答模式（未装 `dsh-free-search`） | 8 | 2.0 KB | 1.2 K 字符 |
| 问答模式（只留 7 个工具） | 7 | 3.3 KB | 1.2 K 字符 |

17 个的构成：本插件只声明 4 个（`read`、`read_image`、`web_search`、`web_fetch`）；其余 9 个是 `dsh-free-search` 注册到 Host 层的工具（`research`、`advanced_search` 等），4 个来自宿主（`working_directory`、`sidebar_open` 等）。未装免费搜索时实测为 8 个：本插件的 4 个，加上宿主的 `create_worktree`、`load_workspace_dependencies`、`sidebar_open`、`working_directory`。

## 还能更省：关掉用不上的检索工具

装了 `dsh-free-search` 时，它会把 9 个检索类工具一起注册到 Host 层，本插件无法声明式排除（`restrict` 需要运行时代码，而本项目刻意保持零运行时代码）。在**设置 → 插件 → Free Search → 工具开关**里关掉不用的，schema 会随之从上下文消失：

| 工具 | 建议 | 理由 |
|---|---|---|
| `web_search` / `web_fetch` | 保留 | 基础能力 |
| `advanced_search` | 保留 | 唯一支持时间过滤的检索 |
| `research` | 保留 | 一次拿多源证据包 |
| `platform_search` | 按需 | 只在查 GitHub/B站/知乎等站内内容时用 |
| `weather` | 按需 | 天气类问题走专用源更准 |
| `multi_search` | 可关 | 与 `advanced_search` 功能重叠 |
| `cache_search` | 可关 | 只在反复查同一批页面时有价值 |
| `free_search_test` | 可关 | 诊断用，问答时不需要 |
| `video_search` | 可关 | 问答很少需要视频结果 |
| `domain_search` | 可关 | 垂直源直查，专业场景才用 |

实测只留 7 个工具时 schema 为 3.3 KB，比 17 个的 11.7 KB 再省 72%。
